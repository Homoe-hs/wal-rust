# 加载策略实验设计:#2 cache-only × #3 惰性(不物化)

> 状态:✅ **已跑,结论见 [`load-strategy-results.md`](load-strategy-results.md)**。目的:决定两条候选路线**各自在什么条件下值得采用**,
> 而不是"看起来更快就上"。所有测量都用 `WAL_PROF=1` 的阶段账(见 [`profiling.md`](profiling.md))。

## 0. 两个候选

| 代号 | 做法 | 直接针对 | 代价 |
|---|---|---|---|
| **#2 cache-only** | `.fnames` + `.ftl`(+ 该信号的 `.fcol`)齐备且指纹匹配时,**完全不 `dlopen`/`open` NPI** | 每次进程那 **4.3s** 的 `npi_fsdb_open` + 许可依赖 | 需要"缓存齐备"这个前提;要能判定"齐备" |
| **#3 惰性 / 不物化** | 不建 `Vec<Sig>`(1796 万条)、不建全量名字索引;名字/列按需解析 | 加载期 **0.7~4.7s** 的名字物化 + **4.5GB** 常驻 | 每次按需解析有常数成本;重复查询可能重复付 |

今天已测到的基线(真波形 336MB / 1796 万信号,暖缓存):

```
load 5.77s = fsdb:open 4.27s + fsdb:names 0.65s + fsdb:index 0.82s   (重叠已上线)
600 个查询 0.65s(每个 ≈1ms)
```

## 1. 四象限(小/大 × 单次/多次)

**"小/大"用 `npi_fsdb_open` 的时间定义**(它才是 #2 的靶子):

| | **单次查询**(只问一件事) | **多次查询**(同一波形问 N 件事) |
|---|---|---|
| **小波形**<br>(open < 0.5s;例:`.tools/bench/v2f/many4m.fsdb`,3.6MB / 400 万信号 / 200 时间点) | **① 小·单** | **② 小·多** |
| **大波形**<br>(open 4~5s;例:336MB 真波形) | **③ 大·单** | **④ 大·多** |

每格都要测**两遍状态**:`冷缓存`(首次,必须走 NPI 树/写缓存)与`暖缓存`(缓存齐备)。

## 2. 每格要采集的量(一次运行全部拿到)

| 量 | 来源 |
|---|---|
| `load` / `fsdb:open` / `fsdb:names` / `fsdb:index` | `WAL_PROF=1` 阶段账 |
| 第 1 个查询、第 N 个查询的耗时 | 阶段账 `probe ×N` 与总墙钟 |
| 峰值 RSS | `/usr/bin/time -f %M` |
| 是否需要许可 | 在**许可 VM 停机**下再跑一遍(见 §4) |
| 结果正确性 | 与现状输出**逐行 diff**(`diff <(...) <(...)`) |

## 3. 每格的假设与判据(先写死,免得事后解释)

| 格 | 假设 | 判据(通过 = 采用) |
|---|---|---|
| ① 小·单 | #2 可能**亏**(校验缓存的固定开销 > 省下的 <0.5s open);#3 无所谓 | #2:`load` 变化 ≤ +10% **且**能省掉许可 → 采用(省许可也算收益);否则**只在"无许可环境"开启**。#3:无回归即可 |
| ② 小·多 | `--stdin` 已经够了;#2 边际收益小 | #2:`load` 降 ≥30% 才采用;否则维持现状 |
| ③ 大·单 | #2 直接砍掉 4.3s;#3 再砍 0.7s(但一次性成本可能更贵) | #2:`load` 降 ≥50%;#3:首次查询 ≤ 现状 **且** 峰值 RSS 降 ≥50% |
| ④ 大·多 | 两者都赢;且要验证 #3 不会"每个信号重复解析" | #2:同上;#3:第 2..N 个查询不得比现状慢(`probe` 总时长 ≤ 现状 ×1.1),稳态 RSS 降 ≥50% |

> 另加一条**全局否决门**:任何一条路线只要让**结果不一致**(逐行 diff 有差异)或让
> **`count_matches` 与 `find_indices().len()` 不一致**,立即停,不进下一步。

## 4. 怎么跑(每格同一条命令,只换波形与探针数)

```bash
# 阶段账 + 峰值 RSS(冷/暖各一次: 冷 = 先 rm 掉该波形的缓存目录)
/usr/bin/time -f "RSS=%MKB" env WAL_PROF=1 ./target/release/wal-rust --stdin -l "$WAVE" < "$PROBES" 2>&1 | tee run.log

# 结果正确性对拍(对照组 = 当前 main 的二进制)
diff <(./target/release/wal-rust --stdin -l "$WAVE" < "$PROBES") \
     <(../wal-rust.main/target/release/wal-rust --stdin -l "$WAVE" < "$PROBES")

# "无许可"这一列(必测): 许可 VM 停机 + 清掉 NPI 相关环境变量
env -u VERDI_HOME -u WAL_NPI_LIB -u SNPSLMD_LICENSE_FILE -u LM_LICENSE_FILE \
    ./target/release/wal-rust '(length (SIGNALS))' -l "$WAVE"
```

探针集:单次 = 1 条 `(length (SIGNALS))`;多次 = 600 条 `(count (changes "<sig>"))`
(与 BTTF 对照实验用的是同一批信号,便于横向比 —— 那份记录在 dev 分支 bttf-waveform-db 上)。

## 5. 预期结论(待验证,写下来是为了可被证伪)

1. **#2 的收益 ≈ `npi_fsdb_open` 的时间** —— 所以它**只在大波形上显著**;
   小波形上收益 <0.5s,但"**不依赖许可**"这条在所有格子都成立,可能才是它真正的采用理由。
2. **#3 的收益 ≈ 名字物化的时间与内存**(0.7~4.7s / 4.5GB),但它把成本从"每次进程一次"
   改成"每次用到某个信号一次" → **在 ②/④(多查询)上必须证明不会重复付**;
   在 ①/③(单查询)上它是最纯粹的赢。
3. 两条路线**叠加**的形态就是"侧车 v3":mmap + 零拷贝 arena + 按需解析 —— 这正是
   `docs/fsdb-rust-backend-spec.md` 里那条 M0 之外的工程路线,与 FSDB 逆向**互不依赖**。

## 6. 与已上线改动的区别

* **已上线**(`dev/profiling`):名字解码与 `npi_fsdb_open` **重叠**(实测 `load` 7.66s → 5.77s,
  600 探针结果逐行一致)—— 这条不需要实验,证据已足够,可直接进 main。
* **本文档讨论的 #2/#3**:会改变"**要不要 open NPI**"和"**要不要物化全表**"这两个架构决策,
  所以先按四象限出数,再决定。
