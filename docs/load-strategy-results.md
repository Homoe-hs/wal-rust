# 加载策略实验结果:#2 cache-only × #3 惰性

> 状态:✅ **已跑并给结论**(2026-10-17,分支 `dev/load-strategy`)。
> 实验设计见 [`load-strategy-experiments.md`](load-strategy-experiments.md)(判据在该文 §3,先写死后跑)。
> 被测二进制 0.14.52 + 本分支原型;真波形 = `aicore_smoke_test_000.fsdb`(336MB / 1796 万信号),
> 小波形 = `.tools/bench/v2f/many4m.fsdb`(3.6MB / 400 万信号 / 200 时间点);缓存均**暖**。

## 0. 一句话结论

| 路线 | 结论 | 依据 |
|---|---|---|
| **#2 cache-only** | ✅ **采用**(当前以 `WAL_FSDB_CACHE_ONLY=1` 选择性开启) | 大波形 load **5.29s → 1.05s(−80%)**、整进程 6.42s → **1.85s**、RSS −30%;小波形 load −30%;且**完全不需要 NPI/许可**;四格结果逐字节一致 |
| **#3 惰性(名字索引)** | 🟡 **只作附带小改进,不作独立路线** | 元信息类查询 load −12%(大)/ −49%(小);真实查询(名字/列)**中性**;峰值 RSS 只 −1%,达不到设计判据的 −50% |
| **#3 真正的"不物化"** | ⏭ **需要缓存格式 v3**(偏移表 + 并行解码/零拷贝 arena),另立项 | 常驻里 2.85GB 是名字 arena 本身;不换格式消不掉 |

## 1. #2 cache-only(完全不碰 NPI)

命令(每格同一条,只换波形/探针数;对拍时过滤 NPI 横幅):

```bash
# normal
WAL_PROF=1 /usr/bin/time -f "%e %M" target/release/wal-rust --stdin -l "$WAVE" < probes
# cache-only(同一二进制, 环境变量切换)
WAL_FSDB_CACHE_ONLY=1 WAL_PROF=1 /usr/bin/time -f "%e %M" target/release/wal-rust --stdin -l "$WAVE" < probes
```

| 格 | 探针(×N) | normal:wall / load / RSS | cache-only:wall / load / RSS | load | 值一致 |
|---|---|---|---|---|---|
| ① 小·单 | `(length (SIGNALS))` ×1 | 0.17s / 0.159s / 403MB | **0.11s / 0.111s / 218MB** | **−30%** | ✅ |
| ② 小·多 | 同上 ×20 | 0.17s / 0.157s / 403MB | **0.11s / 0.106s / 218MB** | **−32%** | ✅ |
| ③ 大·单 | `(count (changes "…core_clk"))` ×1 | 6.42s / 5.292s / 6344MB | **1.85s / 1.051s / 4437MB** | **−80%** | ✅ |
| ④ 大·多 | 同上 ×20 | 5.82s / 4.736s / 6343MB | **1.87s / 1.065s / 4437MB** | **−78%** | ✅ |

**许可**:把 `VERDI_HOME` / `WAL_NPI_LIB` / `SNPSLMD_LICENSE_FILE` / `LM_LICENSE_FILE` 全部去掉后,cache-only 仍能答出
`(length (SIGNALS)) => 4000000` 与 `(timescale) => 1ps` —— 这条路线**从根本上不需要 Verdi 许可**(连 `libNPI.so` 都不 dlopen)。

判据对照(设计 §3):①"load 变化 ≤ +10% 且能省许可" ✅;②"load 降 ≥30%" ✅(−32%);
③"load 降 ≥50%" ✅(−80%);④ 同 ③ ✅(−78%)。**四格全过**。

## 2. #3 惰性:名字索引改为按需构建

同一二进制 A/B:`WAL_FSDB_EAGER_INDEX=1` = 旧行为(加载时就建索引),不设 = 新行为(首次解析名字才建)。

| 格 | 探针 | eager | lazy | 结论 |
|---|---|---|---|---|
| 大·单 | `(length (SIGNALS))` | 7.02s / 6191MB / load 6.673s | **6.16s / 6124MB / load 5.760s** | −0.86s(−12%),RSS −1% |
| 大·多 | 同上 ×20 | 6.68s / 6189MB / load 6.350s | 6.02s / 6124MB / load 5.693s | −0.66s |
| 大·单 | `(count (changes "…"))` | 6.58s / 6197MB / load 6.207s | 6.63s / 6190MB / load 5.575s | **中性**(解析名字仍会建索引) |
| 小·单 | `(length (SIGNALS))` | 0.32s / 433MB / load 0.313s | **0.16s / 393MB / load 0.154s** | **−49% load** |
| 小·单 | `(count (changes "…"))` | 18.54s / 2203MB / load 0.293s | 18.53s / 2203MB / load 0.141s | 中性(列扫描主导) |

判据对照(设计 §3):③ 要求"首次查询 ≤ 现状 **且** 峰值 RSS 降 ≥50%"——时间 ✅、**RSS 只 −1%** ❌;
④ 要求"稳态 RSS 降 ≥50%" ❌。⇒ 作为独立路线**不采用**;作为"元信息类查询"的附带改进**保留**。

## 3. 为什么 #3 的 RSS 目标达不到

加载期常驻(暖,真波形):名字 arena **2.85GB** + spans 144MB + 名字索引 ~400MB + scope ~100MB + NPI/其它 ≈ 2.7GB。
把索引改成惰性只省 ~65MB(实测),因为**真正的大头是名字 arena 本身**。要拿到 −50% 只能:
① 名字不整体解码(需要 `.fnames` v3:偏移表 + 按需读 + 并行解码/零拷贝);② 不建 `Vec<Sig>`(1796 万条)。
两者都在"缓存格式 v3"这个独立项目里,不在本实验范围。

## 4. 采用结论与后续动作

**#2(已实现,选择性开启)**
- 开关:`WAL_FSDB_CACHE_ONLY=1`(非 `strict` 时缺侧车会回退 NPI;`strict` 则报错)。
- 侧车要求:`.fnames`(必需)+ `.ftl`(时间线)+ 该查询信号的 `.fcol`(列);`.fmeta`(时间单位/时间范围,本次新增)。
- 已补齐正确性:cache-only 的 `(timescale)`/`(MAX-INDEX)` 与正常路径一致(靠 `.fmeta`)。
- **未做**(下一步):侧车完整性自动判定 + 自动开启 + 无侧车时静默回退。做之前保持环境变量显式开启。
- 已知限制:小文件不一定落 `.fcol`(小文件策略),所以小波形上 cache-only 只能服务"元信息类"查询;
  冷缓存(cache-only 无侧车)自然不适用。

**#3(部分保留)**
- 名字索引惰性构建已改(默认开):正确性一致(所有对拍 `yes`),元信息查询更快、常驻略降;真实查询中性、无回归。
- 不物化的"大版本"需要 v3 格式,建议单独立项(目标:暖加载 RSS ≤3GB、名字解码 ≤1s)。

## 5. 测量环境与噪声(引用这些数字时必须一起看)

- 许可通道**不稳**:每次 `.tools/vm/license_up.sh` 可能要等 VM 重启(实测单次 3 分钟级),脚本里已改成"失败才重试"。
- NPI 横幅打 **stdout**,normal 路径的输出对拍前要先过滤(`grep '^=>'`);
- cache-only 路径**没有**横幅与 `[prof]` 的 `fsdb:open` 段(它本来就不 open),阶段账里 `load` 通常仍有(名字+索引)。
- 一次 `(count (changes …))` 若该信号没有 `.fcol`,会先付一次**冷列扫描**(小夹具实测 18.5s/次),
  这类格子测出来的"normal 慢"是列扫描,不是加载差异 —— 所以大波形格子特意选了已缓存的 `core_clk`。
